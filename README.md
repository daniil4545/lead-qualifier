# lead-qualifier

Движок квалификации лидов для B2B-услуг. Бот переписывается с лидом, который оставил заявку: отвечает на вопросы по базе знаний, собирает пять фактов о компании, решает, звать ли на встречу, и записывает к менеджеру. Модель ведёт разговор и приносит факты, а решает детерминированный код на Go.

Проект читается за вечер: консольное демо, фейковая CRM, Postgres в Docker, ключ OpenRouter.

## Как устроено

Один ход агента - это цикл вызовов модели с native tool calling: `search_kb`, `save_facts`, `complete`, `offer_slots`, `book_slot`, `escalate`, `refuse`, `stop_contact`. Ход ничего не пишет сам и возвращает недоверенный результат, а применяет его код.

- **Go проверяет ход до действия.** Окна и бронь недоступны до вердикта ниши, до полного набора фактов, при закрытом гейте и при уже назначенной встрече. Запрет отвечает модели ответом инструмента, и dialog перепроверяет его ещё раз перед бронью.
- **Решает код.** Гейт записи считает сегмент ниши, пороги выручки и тарифы из каталога: цену по нижней границе выручки, допуск по верхней. Нишу раскладывает отдельный вызов-классификатор, его ответ сверяется с кодами каталога.
- **Guard** режет в тексте модели чужие цены, суммы при неизвестном тарифе, имена третьих лиц с падежами и в транслите, телефоны, почту, ссылки вне каталога и пересказ внутренних правил. Нарушение отправляет черновик на перегенерацию, а не лиду.
- **Критик** - отдельный strict-JSON вызов, который проверяет каждый черновик: факты только из выданных фрагментов базы, никаких обещаний и манипуляций.
- **Состояние в Postgres.** Кейс - проекция, решения и события - журнал. Ответ лиду, заметка и задача в CRM, бронь пишутся одной транзакцией с решением через outbox. Двойную бронь отбивает уникальный индекс (менеджер, начало), а не подбор окон.
- **Сбой модели** не становится решением: ход откладывается и переигрывается, после трёх повторов кейс уходит к человеку.

Модель кейса, рубежи и решения - в [docs/architecture.md](docs/architecture.md).

## Быстрый старт

Нужны Go, Docker и ключ OpenRouter.

```sh
export OPENROUTER_API_KEY=...
make demo
```

Демо спрашивает имя лида, заводит заявку в фейковой CRM, и бот пишет первым. Дальше каждая строка ввода - реплика лида. Записи CRM печатаются строками `[CRM ...]`, логи уходят в `demo.log`. Модель по умолчанию `google/gemini-2.5-flash` задана в `data/example/config.json`, переопределяется `OPENROUTER_MODEL`.

## Каталог: свой бизнес без правки кода

Всё, что отличает одного клиента от другого, лежит в папке каталога (`CATALOG_DIR`, по умолчанию `data/example`):

- `config.json` - компания, персона и её род, часовой пояс, рабочие часы, длительность встречи, модель, тарифы (порог, имя, цена), сегменты ниш с порогами, поводы отказа, менеджеры, ссылки;
- `texts.json` - приветствие и готовые ответы кода;
- `prompts/` - агент, критик, классификатор ниши;
- `knowledge/` - база знаний для `search_kb`, `stop_names.txt` - кого бот не называет;
- `golden/` и `niche_cases.tsv` - эталоны для оценки.

Старт проверяет каталог: пороги сегментов не ниже минимального порога тарифов, в базе знаний только цены тарифов и ссылки каталога, без телефонов и стоп-имён. В Go-коде нет ни одного значения каталога, это держит тест. Общность проверяет второй каталог `testdata/catalog-alt`: другая компания, пороги, тарифы, пояс, длительность встречи и персона. Тот же табличный тест гоняет оба каталога. Чтобы подключить свой бизнес, достаточно скопировать `data/example`, заполнить его и запустить с `CATALOG_DIR=путь`.

## Оценка промптов

```sh
make prompteval ARGS="-n 3"
```

Каждый эталон из `data/example/golden` прогоняется n раз через живую модель. Отчёт показывает долю прошедших, опасные исходы и классы расхождений. Прогоны, упавшие на транспорте, считаются отдельно, и при них команда выходит с ошибкой. `-prompts` оценивает кандидата промптов на той же базе знаний, `-out` сохраняет отчёт в JSON.

Эталоны - это 15 классов, по одному ходу на класс: от полного набора фактов и вопроса по базе до инъекции, настойчивого вопроса о цене, выбора окна и переноса встречи. Эталон проверяет действие хода, аргументы инструмента, снимок фактов и запрещённые подстроки в ответе. Смысл и качество текста он не оценивает, это остаётся за критиком и человеком.

Офлайн-проверка эталонов и остальные тесты:

```sh
make test-fast   # без базы
make test        # с Postgres из docker-compose
```

Живой тест классификатора ниши по `niche_cases.tsv` включается переменной `LQ_LIVE_MODEL=1`.

## Пакеты

| Пакет | Что внутри |
|---|---|
| `config` | окружение и каталог, проверка при старте |
| `qualify` | кейс и статусы, факты, тарифы, ниша, гейт |
| `knowledge` | база знаний и её проверка |
| `crm` | интерфейс CRM и фейк в памяти |
| `calendar` | свободные окна менеджеров |
| `agent` | цикл хода, OpenRouter, guard, критик, классификатор ниши, промпты |
| `store` | Postgres: кейсы, сообщения, решения, брони, outbox |
| `dialog` | обработчик: захват кейса, ход, применение решения, доставка |
| `console` | транспорт демо |
| `eval` | эталоны и оценка хода |

Команды: `cmd/lead-qualifier` (`demo`) и `cmd/prompteval`.
